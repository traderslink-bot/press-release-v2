## Current v2 Post Format

The current live `v2` embed format is:

- title:
  - `$TICKER`
- description:
  - spacer under title
  - bold article headline
  - snapshot line with:
    - `Float`
    - `IO`
    - `MC`
    - `Filing Type`
  - optional dilution block with bold labels
  - summary
  - description-bottom spacer to improve the visual gap above `Positives`
- fields:
  - `Positives`
  - `Negatives`
  - levels block
  - `SEC Filing Link` only for SEC posts

Formatting rules currently intended:

- no `Signal Details` block
- no non-SEC bottom link
- title is not linked
- levels render as:
  - `**Resistance:** ...`
  - `**Support:** ...`
  - blank line
  - `Data generated during ...`

## Current Fallback Behavior

For non-SEC article failures:

- live post should no longer say:
  - `Article text unavailable; summary based on raw Discord metadata.`
  - `Full article text unavailable ...`
- fallback-status negatives that mention unavailable article text are also stripped from the live post

Important:

- debugging data still exists in:
  - ingest DB
  - live fetch log

So the live Discord output is cleaner, but the system still retains the real fallback reason.

## Current Resilience Additions

`v2` now includes:

- delayed retry for retryable OpenAI failures
  - one deferred retry after 60 seconds
- supervisor loop around live Discord bot
  - restarts after crash/exit
- watcher heartbeat from the injected Discord page
- periodic rescans of visible host-channel messages
- idle warnings if no host posts have been seen for an unusual amount of time

This improves stability, but it does not perfectly prove every missed host post after the fact.
